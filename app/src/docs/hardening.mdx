Sigillo encrypts every secret, but the key lives in the Worker that decrypts them. [How Sigillo protects your secrets](./security.mdx) shows who can reach them; these steps narrow each of those, most important first.

## 1. Give Sigillo its own Cloudflare account

Cloudflare hides a secret's value once it's set, in the dashboard and in Wrangler. Code running in the Worker can still read it, so **anyone who can deploy Workers on the account can read every secret**. Anyone who can edit its D1 databases can make any account that signs in an org admin.

- Deploy into an account that holds nothing but Sigillo: `npx @kldzj/sigillo self-host --account <id>`.
- Keep its members few. Under **Manage Account → Members**, a Super Administrator can turn on **2FA Enforcement**, so every member needs two-factor authentication.
- Give people who only need to look a read-only role, such as **Administrator Read Only** or **Workers Platform (Read-only)**. **Administrator** and **Workers Platform Admin** can deploy Workers.

## 2. Protect the deploy file

`~/.sigillo/selfhost.json` holds the keys that decrypt every secret and sign every session. Keep its passphrase in your password manager and a backup of the file somewhere else: without both, a lost worker means lost secrets. Deploy with a Cloudflare API token that has a TTL and an IP filter rather than a saved browser login. See [your deploy file](./updating.mdx#your-deploy-file) and [deploying with an API token](./updating.mdx#deploy-with-an-api-token).

## 3. Decide who can sign in

By default anyone with a Google account can create an account on your instance. Limit it to your addresses and domains with the [sign-in allowlist](./self-hosting.mdx#who-can-sign-in), and, for a Google Workspace, make the OAuth client **Internal**: see [who can sign in](./access.mdx#who-can-sign-in).

## 4. Limit access inside Sigillo

Keep org admins few: an admin reaches every project and environment of the organization. Limit members to the projects they work on, and make production [admin-only](./access.mdx#admin-only-environments). See [Teams and access](./access.mdx).

## 5. Protect production with passkeys

Set **Protected** to **On** for production. Reading or changing it then takes a passkey, every read is recorded, and admin actions in the organization take a passkey too. Have everyone add two passkeys. See [protected environments and passkeys](./protected-environments.mdx).

## 6. Give machines the narrowest credential

Use [workload identity](./workload-identity.mdx) for GitHub Actions and Kubernetes, so nothing is stored. Elsewhere, make one [token](./ci.mdx) per machine or pipeline, scoped to the environments it needs, and a machine token only where it must reach a protected environment.

## 7. Check the history regularly

Run `sigillo audit verify` for your protected environments, from more than one admin's machine. See [the signed history](./history.mdx).

## 8. Keep your own backups

Make [encrypted backups](./backups.mdx) with `self-host --backup` and keep them outside Cloudflare, next to a copy of your deploy file. Make a new one after every [key rotation](./rotate-key.mdx).

When someone leaves your team, follow [when someone leaves](./offboarding.mdx).
